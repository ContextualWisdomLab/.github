## Added

- Added a strict inert-data verifier foundation for scientific-validation evidence (#2299 / PR #2300). It binds exact repository/head/run identity, profile and pre-execution chronology, exact-head test receipt/artifact state, seed manifest, grouped recovery evidence, ordered replication provenance, and per-replication execution artifact identities into a versioned scientific-validation predicate while explicitly leaving psychometric acceptance to TEPP.
- Hardened verifier output authority in #2301: predicate and manifest destinations must be distinct, must remain outside the sealed evidence root, and must not traverse symlinked/non-directory parent ancestry before publication.
- Hardened evidence intake identity in #2302: the verifier opens the sealed leaf without following symlinks, reads one bounded byte snapshot, and derives both SHA-256 and strict JSON semantics from those exact bytes. This removes the prior hash-then-reopen TOCTOU gap. The atomic writer's own leaf-symlink refusal is now covered directly rather than being shadowed by the earlier output-path gate.
- Hardened non-regular input refusal in #2303: the untrusted sealed member is opened with `O_NONBLOCK` as well as `O_NOFOLLOW` before its type is known, so a FIFO or other special file cannot stall the verifier before the descriptor-level regular-file check rejects it.
- Hardened sealed-root authority in #2304: the verifier now pins the evidence directory through a component-wise `O_DIRECTORY | O_NOFOLLOW` descriptor walk, enumerates that pinned directory descriptor, and opens the sole evidence member relative to the same descriptor. Replacing the validated root pathname with a symlink can no longer redirect which inode supplies the attested bytes.
- Hardened output publication authority in #2305: each output parent is pinned by descriptor before evidence verification, and temporary-file creation plus final publication operate relative to that descriptor. Renaming a validated output directory and replacing its pathname with a symlink can no longer redirect predicate or manifest publication.
- Hardened fresh-receipt publication in #2306: both output leaves must be absent before evidence verification, and the final publication primitive uses descriptor-relative no-clobber hard-link creation rather than replacement. Stale or concurrently created receipt paths are rejected without overwrite, and final publication collisions or I/O failures become typed verifier errors.
- Bound paired verifier receipts in #2307: the manifest is published last as the completion marker and now carries `predicate_sha256`, the SHA-256 of the exact canonical predicate bytes. If manifest publication loses a no-clobber race, the invocation fails and any lone predicate is explicitly incomplete rather than a completed receipt pair. The credentialed signer must require successful verifier completion plus a matching manifest commit marker before signing.
- Reconciled the verifier's deterministic-output tests in #2308 with #2306 no-clobber semantics: determinism is now checked across independent fresh invocations, and temporary-file cleanup is exercised against the current hard-link publication failure path rather than the removed `replace(2)` path.
- Versioned the unsigned signer handoff in #2309: the final completion manifest now carries the owner-defined `https://contextualwisdomlab.org/attestations/scientific-validation-manifest/v1` type plus schema version `1.0`. A reusable strict manifest validator enforces the closed field/type contract and recomputes `predicate_sha256` from the exact canonical predicate bytes before the marker is accepted for later signer consumption. The manifest type is intentionally independent from the scientific predicate type so future breaking handoff changes cannot silently reuse the same owner API identity.
- Hardened temporary receipt creation in #2310: temporary inode names now use a bounded fixed prefix independent of the final output leaf, so a valid near-`NAME_MAX` receipt path does not become an invalid temporary filename. Temporary creation `OSError`s are normalized to typed `EvidenceError`s while descriptor-relative `O_EXCL | O_NOFOLLOW`, fsync, no-clobber hard-link publication, and cleanup remain unchanged.
- Cross-bound the versioned completion marker to the exact predicate semantics in #2311: `validate_receipt_manifest` now strictly validates the committed predicate schema and explicit non-scientific claim boundary, then requires every duplicated repository/run/predicate/artifact/evidence/execution identity in the manifest to equal the corresponding value inside the exact predicate bytes. A syntactically valid contradictory manifest can no longer become signer policy input merely because its `predicate_sha256` is correct.
- Repaired the #2310 cleanup regression contract in #2312: the hard-link failure test now recognizes the bounded `.scientific-validation-<uuid>.tmp` source and searches that exact temporary namespace for leaks, so the exact-head quality job exercises typed publication failure instead of failing on the obsolete final-leaf-derived prefix.
- Hardened strict JSON parser failure normalization in #2313: hostile but byte-bounded integer tokens beyond Python's conversion limit and excessive nesting now fail with deterministic `EvidenceError` instead of escaping as raw `ValueError` or `RecursionError`; duplicate-key, non-finite-number, and ordinary JSON syntax diagnostics retain their owner-defined rejection paths.
- Bound immutable GitHub artifact size metadata in #2314: `evidence_artifact_size_in_bytes` is now a required positive-decimal control, is committed into both the scientific-validation predicate and versioned completion manifest, and is cross-validated by `validate_receipt_manifest` alongside artifact ID, name, and digest. The value remains independent GitHub artifact metadata and is not inferred from the extracted evidence-member byte length.
- Added bounded signer-facing receipt intake in #2315: manifest and predicate leaves are opened once as regular files through pinned unsymlinked parent descriptors, each file is capped at 4 MiB, and the exact bytes are delegated to the strict receipt validator.
- Rejected hard-link role aliasing in #2316: the manifest and predicate may not resolve to the same `(st_dev, st_ino)` even when different pathnames are supplied, preventing one physical file from being replayed as both receipt roles.
- Pinned paired-read parent authority in #2317: both receipt parent directories are acquired before either leaf is read, and a shared normalized parent is opened exactly once so a pathname-generation swap cannot splice manifest and predicate from different directory authorities.
- Pinned paired-output parent authority in #2318: predicate and manifest publication now shares one descriptor when both leaves use the same normalized parent, while distinct output parents retain independent pinned descriptors. A pathname-generation swap cannot split one logical receipt pair across two directory generations.
- Rejected sealed-root rename aliases in #2319: every acquired output-parent descriptor is compared with the pinned evidence-root descriptor by `(st_dev, st_ino)`, so renaming the sealed evidence directory onto an allowed output pathname cannot make receipt publication mutate the verified evidence inode.
- Added crash-durable receipt publication in #2320: after descriptor-relative no-clobber hard-link creation, the verifier fsyncs the already-pinned output-parent directory before returning success. Directory synchronization failures are normalized to `EvidenceError`; the linked leaf is not rolled back through an unsafe pathname race. This follows POSIX/Linux `fsync(2)` guidance that syncing a file does not itself guarantee durability of the containing directory entry.
- The verifier is not a signer and does not claim OIDC/Sigstore/GitHub Artifact Attestation authority. Credentialed reusable-workflow signing remains gated on the current #2164 reusable-workflow identity prerequisite and its exact-head review/gates; closed #2133 is not a live prerequisite.
