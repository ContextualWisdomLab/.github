## Added

- Added a strict inert-data verifier foundation for scientific-validation evidence (#2299 / PR #2300). It binds exact repository/head/run identity, profile and pre-execution chronology, exact-head test receipt/artifact state, seed manifest, grouped recovery evidence, ordered replication provenance, and per-replication execution artifact identities into a versioned scientific-validation predicate while explicitly leaving psychometric acceptance to TEPP.
- Hardened verifier output authority in #2301: predicate and manifest destinations must be distinct, must remain outside the sealed evidence root, and must not traverse symlinked/non-directory parent ancestry before publication.
- Hardened evidence intake identity in #2302: the verifier opens the sealed leaf without following symlinks, reads one bounded byte snapshot, and derives both SHA-256 and strict JSON semantics from those exact bytes. This removes the prior hash-then-reopen TOCTOU gap. The atomic writer's own leaf-symlink refusal is now covered directly rather than being shadowed by the earlier output-path gate.
- Hardened non-regular input refusal in #2303: the untrusted sealed member is opened with `O_NONBLOCK` as well as `O_NOFOLLOW` before its type is known, so a FIFO or other special file cannot stall the verifier before the descriptor-level regular-file check rejects it.
- Hardened sealed-root authority in #2304: the verifier now pins the evidence directory through a component-wise `O_DIRECTORY | O_NOFOLLOW` descriptor walk, enumerates that pinned directory descriptor, and opens the sole evidence member relative to the same descriptor. Replacing the validated root pathname with a symlink can no longer redirect which inode supplies the attested bytes.
- Hardened output publication authority in #2305: each output parent is pinned by descriptor before evidence verification, and temporary-file creation plus final publication operate relative to that descriptor. Renaming a validated output directory and replacing its pathname with a symlink can no longer redirect predicate or manifest publication.
- Hardened fresh-receipt publication in #2306: both output leaves must be absent before evidence verification, and the final publication primitive uses descriptor-relative no-clobber hard-link creation rather than replacement. Stale or concurrently created receipt paths are rejected without overwrite, and final publication collisions or I/O failures become typed verifier errors.
- Bound paired verifier receipts in #2307: the manifest is published last as the completion marker and now carries `predicate_sha256`, the SHA-256 of the exact canonical predicate bytes. If manifest publication loses a no-clobber race, the invocation fails and any lone predicate is explicitly incomplete rather than a completed receipt pair. The credentialed signer must require successful verifier completion plus a matching manifest commit marker before signing.
- Reconciled the verifier's deterministic-output tests in #2308 with #2306 no-clobber semantics: determinism is now checked across independent fresh invocations, and temporary-file cleanup is exercised against the current hard-link publication failure path rather than the removed `replace(2)` path.
- The verifier is not a signer and does not claim OIDC/Sigstore/GitHub Artifact Attestation authority. Credentialed reusable-workflow signing remains gated on the current #2164 reusable-workflow identity prerequisite and its exact-head review/gates; closed #2133 is not a live prerequisite.
