### ADR-0030 settles what may bound a review provider call, before the pin advance removes the only bound there is

- `contextual-orchestrator#1118` changed `ModelClient.__init__`'s `timeout` default from `int = 90` to `float | None = None`. That removal is correct -- an implicit 90-second cap on the inference path is what ADR-0003's 2026-08-31 amendment forbids and what `#1889`/`#1890`/`#1892` were reverted for reintroducing -- but three layers then decline to bound the call: the library default is `None`, `contextual_orchestrator_review_launcher.py:1240` passes no `timeout`, and `noema-review.yml:261` states "No job-level `timeout-minutes` here, deliberately." Nothing below GitHub's six-hour job ceiling remains. Production evidence for what the cap is currently doing, from `#1884` head `e85fc437` (run 34732993973, sidecar stderr artifact 10310273053): the serving phase made fifteen provider attempts in 907.3s across two agents on two credential accounts, and eight of the ten measured attempt-to-failure durations land on exactly 90.0s -- roughly 720 of the 907 seconds is the default expiring against sockets that accepted a connection and delivered nothing. The same trace shows the cap discarding a route on no evidence of failure (`google/gemma-4-31b-it` rejected at preflight after exactly 90.0s), so the org currently holds both defects at once: a cap that kills slow-but-working models, and no bound at all on a dead socket once it is removed. ADR-0030 decides that occupancy is bounded by **progress, not elapsed time**: an idle-socket bound reset on every byte received (a response that is streaming is never interrupted at any duration; a connection that has produced nothing since the request was written is not slow inference), continuation admission so a breaker reset does not re-offer the failing agent while preflight-`ready` alternatives sit untried (that run cycled two routes fifteen times while two ready routes on the same accounts were never tried), and runner reclamation emitted as its own job-boundary event rather than attributed to the provider. It states explicitly that an idle-socket bound is not the reverted wall-clock deadline, because it cannot expire on a request that is making progress -- the question the reverts turned on, settled in writing rather than in code review. No total-duration limit on a review, model, or request is introduced, and no threshold value is named until time-to-first-byte across the pool is measured. Refs #1884, #1915, #2137, #2139, ContextualWisdomLab/contextual-orchestrator#1118.
