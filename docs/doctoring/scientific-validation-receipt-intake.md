# Scientific-validation signer receipt intake

Issue #2315 closes the byte/file boundary between the unsigned scientific-validation verifier in #2300 and the future credentialed signer owned by #2299. `validate_receipt_manifest()` remains the semantic authority for the versioned manifest/predicate pair; the signer-facing reader controls how those exact bytes enter that validator. Issue #2316 tightens that boundary further by requiring the two receipt roles to resolve to distinct regular-file inodes, not merely distinct path strings. Issue #2317 additionally requires the parent-directory authorities for both receipt leaves to be acquired before either leaf is read, so one logical pair cannot be assembled across a directory-generation swap.

## Finding

The verifier already bounds the sealed scientific evidence document at 16 MiB, but the signer handoff is a separate trust boundary. A credentialed job that first used an ordinary path read on an attacker-controlled manifest or predicate could allocate or hash an arbitrarily large file before semantic validation rejected it. The signer must therefore bound the file read itself, not merely check the parsed object afterward.

A second filesystem-identity defect remained after the bounded reader landed. Two different pathnames can be hard links to the same regular inode. If the reader only compares absolute path strings, one physical file can occupy both receipt roles. Because the manifest is read first and the predicate second, the shared inode could be rewritten between reads so that the first snapshot is a valid manifest and the second is its pre-committed predicate. The semantic pair can then validate even though the two roles were never represented by distinct inodes at intake time.

A third authority gap remained after descriptor identity was added. The reader pinned and released the manifest parent before opening the predicate parent. A same-host actor could therefore rename the shared receipt directory after the manifest read and replace the original pathname with a different real directory. The second component walk would still be symlink-free, but it would bind the predicate read to a different directory generation. Manifest and predicate could then come from different filesystem authorities while still satisfying their semantic hash bindings.

## Decision

`scripts/ci/validate_scientific_validation_receipt.py` is the signer-facing intake primitive. It normalizes both paths, rejects an identical manifest/predicate pathname, and pins the required parent-directory authorities before either leaf is read. When both leaves share one parent path, the reader opens that directory once and reuses the same descriptor for both leaves. When the leaves use distinct parents, both descriptors are acquired before either leaf is consumed.

Each leaf is opened relative to its already-pinned parent with `O_NOFOLLOW | O_NONBLOCK`, required to be a regular inode by descriptor, and read once up to 4 MiB + 1 byte. Those exact bytes are passed to `validate_receipt_manifest()` without re-serialization. The same `fstat()` call that proves regular-file type captures `(st_dev, st_ino)` for each open descriptor. Manifest and predicate snapshots are refused before semantic validation when those identities match. This avoids a pathname `stat()` race and does not require `st_nlink == 1`; unrelated hard links are allowed unless the two receipt roles themselves resolve to the same inode.

The 4 MiB ceiling is deliberately independent from the 16 MiB scientific-evidence ceiling. One execution-artifact identity occupies roughly 67 bytes in compact JSON (64 hex characters plus quotes/comma overhead), so 4 MiB leaves room for more than 60,000 ordered execution identities before fixed receipt fields are considered. That is far above current scientific acceptance workloads while putting a deterministic upper bound on signer memory and parser work.

Manifest and predicate pathnames must be distinct, their opened descriptor identities must be distinct, and their parent authorities must be pinned before either receipt leaf is consumed. Missing leaves, symlinks, FIFOs/directories, symlinked parents, oversize files, same-inode hard-link aliases, cross-generation parent swaps, and semantically invalid bounded pairs fail closed. `O_NONBLOCK` prevents a FIFO from stalling the signer before the regular-file test executes.

## Boundary

This reader does not authenticate the caller, GitHub run, artifact producer, workflow source, signature, or Sigstore bundle. It does not run caller code, request OIDC, hold attestation permissions, or make psychometric decisions. #2164 remains the reusable-workflow identity prerequisite; #2299 still owns live GitHub metadata verification, credentialed signing, bundle verification, and the immutable released/pinned contract. TEPP #637 remains blocked from commercial attestation authority until that owner path exists.

The owner quality gate covers the reader and its hostile-file contracts at 100% owned line/branch/docstring coverage. The tests exercise valid exact bytes in shared and distinct pinned parents, per-file size refusal before semantic parsing, missing/symlink/non-regular/FIFO/ancestor-symlink objects, identical paths, same-inode hard-link aliases before semantic validation, shared-parent directory-generation replacement, semantic failure after bounded intake, stable CLI exit behavior, executable dispatch, and immutable-sibling bootstrap refusal.
