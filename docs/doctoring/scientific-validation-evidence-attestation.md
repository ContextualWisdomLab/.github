# Scientific-validation evidence attestation boundary

Status: verifier foundation implemented in PR #2300 for issue #2299. The credentialed signer remains blocked on the reusable-workflow identity prerequisite in #2164; no attestation authority is claimed by #2300 alone.

## Problem

TEPP Validation Evidence now carries content identities for the scientific recovery profile, pre-execution represented chronology, exact-head test receipt, seed manifest, grouped recovery evidence, ordered replication provenance, and per-replication execution artifacts. Those identities are internally coherent but their adapter-supplied origin is not authenticated. A leaf repository must not solve that by embedding a signing key, copying GitHub/OIDC code, or treating another repository's mutable branch as production authority.

The organization control plane therefore owns a separate origin/integrity attestation contract. Scientific meaning remains with TEPP: the control plane must never decide RMSE, bias, coverage, convergence, estimator adequacy, construct validity, or `ScientificallySupported` acceptance.

## Implemented verifier foundation

`scripts/ci/verify_scientific_validation_evidence.py` consumes exactly one bounded regular UTF-8 JSON document as inert data. It requires independent controls for:

- caller/source repository and exact Git SHA;
- workflow run identity and immutable GitHub artifact metadata supplied by the future workflow boundary;
- profile and represented pre-execution chronology SHA-256 identities;
- exact-head receipt identity, exact-head underlying artifact identity, and terminal `passed` state;
- ordered seed-manifest, grouped recovery-evidence, and replication-provenance identities;
- an ordered, unique list of per-replication execution-artifact SHA-256 identities.

It rejects path traversal, symlink/non-regular input, extra or missing artifact members, oversized or invalid UTF-8 JSON, duplicate object keys, non-finite JSON constants, schema drift, malformed digests, exact-head failure states, semantic substitutions, execution-artifact reorder/duplication, and evidence-byte digest mismatch. Output is deterministic canonical JSON written atomically per leaf.

Issue #2301 additionally hardens the output authority boundary. Predicate and manifest destinations are validated before publication, must be distinct, must remain outside the sealed one-member evidence root, and must not traverse a symlinked or non-directory parent. This prevents a successful verifier invocation from overwriting its own predicate with the manifest, mutating the sealed evidence set after validation, or redirecting trusted-looking output through a symlinked parent.

Issue #2302 hardens input identity against a hash/parse time-of-check-to-time-of-use split. The verifier no longer hashes a pathname and then reopens that pathname for semantic validation. It opens the leaf with `O_NOFOLLOW`, requires the opened descriptor to reference a regular file, reads at most the configured bound plus one byte exactly once into memory, and uses that same byte snapshot for both SHA-256 comparison and strict JSON parsing. A pathname replacement after the descriptor is opened therefore cannot make the verifier attest bytes that differ from the bytes whose semantics it validated. This remains an unsigned local integrity boundary; it is not a provenance signature.

Issue #2303 closes the special-file availability gap introduced by descriptor-first intake. Because the member's type is unknown until `fstat`, a blocking `O_RDONLY` open could wait indefinitely on a FIFO before the regular-file rejection ran. Intake now requests `O_NONBLOCK` together with `O_NOFOLLOW`; regular files behave normally, while FIFOs/devices cannot hold the verifier at `open(2)` before the descriptor-type guard fails closed.

Issue #2304 closes the remaining sealed-root path-authority gap. The verifier now acquires the evidence root by walking each absolute path component through directory descriptors with `O_DIRECTORY | O_NOFOLLOW`, retains the resulting descriptor while checking one-member cardinality, and opens the evidence filename relative to that same descriptor. A concurrent rename/replacement of the root pathname therefore cannot redirect the subsequent evidence read through a new symlinked ancestor. This is still a local filesystem-integrity control; it does not authenticate who created the directory, evidence bytes, or control values.

Issue #2305 closes the corresponding output-parent path-authority gap. Each predicate/manifest parent directory is acquired through the same component-wise no-symlink descriptor walk before the evidence is read. Publication keeps those descriptors open through verification, creates the temporary receipt relative to the pinned parent, and performs final publication relative to that same directory descriptor. Renaming the validated parent and replacing its pathname with a symlink after validation therefore cannot redirect output publication. This remains a local filesystem-integrity control rather than provenance authentication.

Issue #2306 closes the stale-output and final-publication clobber gap left after parent pinning. Both predicate and manifest leaves must be absent on their pinned parent descriptors before evidence verification begins, and the final writer checks absence again. Publication now creates the final leaf with descriptor-relative hard-link semantics from the already-fsynced temporary regular file instead of replacing an existing leaf. A stale or concurrently created receipt therefore fails closed without overwrite; final publication collisions and I/O failures are normalized to typed verifier errors. This is freshness/integrity hardening for an unsigned receipt, not signer or provenance authority.

Issue #2307 makes the two-file receipt contract explicit instead of pretending POSIX can atomically commit two independent leaf paths. The predicate is published first. The manifest is published last and is the completion marker; it carries `predicate_sha256`, computed from the exact canonical predicate bytes written by the verifier. A failed or raced manifest publication therefore leaves, at worst, an inert predicate that is not a completed receipt pair. We deliberately rejected pathname check-then-unlink rollback: another writer can replace that pathname between identity checking and unlink, turning cleanup into deletion of an unrelated inode. The future signer must require successful verifier exit plus a manifest whose `predicate_sha256` matches the exact predicate bytes before it can sign anything.

Issue #2308 repairs the test contract after #2306 changed publication semantics. Deterministic output is now demonstrated by two independent equivalent invocations with fresh output leaves rather than by rerunning over stale receipts that production must reject. The temporary-file cleanup contract also targets the current hard-link publication path and requires a typed `EvidenceError`, instead of monkeypatching the removed `replace(2)` implementation. No production freshness gate was weakened to satisfy the tests.

Issue #2309 versions the completion-marker contract itself. The scientific predicate already has the major-versioned type `https://contextualwisdomlab.org/attestations/scientific-validation/v1`, but that URI describes the later attestation payload, not the local manifest consumed by the signer. The manifest therefore now carries an independent owner contract identity, `https://contextualwisdomlab.org/attestations/scientific-validation-manifest/v1`, plus schema version `1.0`. `validate_receipt_manifest` strictly parses the marker, rejects missing/unknown fields and malformed identities, checks the owner literals, validates ordered execution-artifact identities, and recomputes `predicate_sha256` from the exact predicate bytes before the marker is accepted. This follows the in-toto/SLSA rule that a breaking claim-schema change receives a new major-versioned type identity; it does not turn the unsigned manifest into authenticated provenance.

Issue #2310 closes a publication-availability edge case found in review. The predecessor derived its temporary inode name from the complete final output filename. A valid receipt leaf near the filesystem `NAME_MAX` could therefore make the temporary name exceed `NAME_MAX`, and the resulting `os.open` error escaped the typed verifier boundary. Temporary names now use a short fixed prefix plus UUID, independent of the final leaf, and temporary-creation failures are normalized to `EvidenceError`. Descriptor-relative exclusive creation, fsync, hard-link no-clobber publication, and cleanup remain unchanged.

Issue #2311 closes an ambiguity between the versioned completion marker and the exact predicate it commits. Before this repair, `predicate_sha256` proved byte identity but duplicated policy fields in the manifest were only syntax-checked, so a syntactically valid manifest could claim a different repository, run, artifact, evidence digest, or execution list while still referencing the correct predicate hash. `validate_receipt_manifest` now strictly parses the exact predicate bytes, preserves the explicit `origin_and_integrity_only` / `does_not_prove` scientific boundary, validates its closed evidence schema, and requires every duplicated manifest field to equal the corresponding predicate/evidence value. The unsigned pair is therefore internally unambiguous for a future signer, but it is still not authenticated provenance until the OIDC/signer owner path is landed and verified.

The generated predicate type is `https://contextualwisdomlab.org/attestations/scientific-validation/v1`. Its claim is limited to `origin_and_integrity_only`; it explicitly records that psychometric numerical acceptance, RMSE/bias threshold success, construct validity, estimator validity, and production equivalence are outside the attestation claim.

## Remaining signer prerequisite

PR #2164 owns the reusable-workflow source-identity repair. It has already been ordinary-forward reconciled to current protected `main` as `a20726c1c4a387bba30e5609d550e36d2b0b3087`; closed #2133 is not a live blocker. Its exact-head gates and qualifying independent review still need to complete before the signer path can treat that identity contract as protected authority. The correct path is normal landing/pinned authority, not copying its mutable implementation into #2300.

After #2164 lands through protected review, #2299 still requires a separate two-phase reusable workflow:

1. an uncredentialed intake job independently re-reads live repository/run/artifact metadata, downloads by immutable artifact ID, and invokes this verifier over the sealed bytes;
2. a credentialed signer job independently re-verifies the same inert evidence, requires successful verifier completion plus the final manifest commit marker, runs `validate_receipt_manifest` over the exact manifest and predicate bytes so byte identity, manifest version, explicit non-scientific claim boundary, and duplicated policy/evidence identities all agree, authenticates reusable-workflow source identity from GitHub OIDC, uses an immutable reviewed `actions/attest` pin, and only then signs the verified scientific-validation predicate;
3. online and offline verification bind caller repository/source SHA, central signer repository/workflow, predicate type, subject digest, GitHub OIDC issuer/trusted root, and the exact evidence identities above.

No caller/product code may execute in a job holding `id-token: write`, `attestations: write`, or artifact-metadata signing authority.

## Consumer boundary

TEPP #637 is the future consumer ACL. It must wait for a released or immutable-pinned organization verifier/attestation contract and then require a verified receipt before commercial scientific authority is exported. TEPP may retain a pure deterministic scientific decision layer for unit/research evaluation, but must not relabel today's trusted-adapter hashes as cryptographically verified evidence.
