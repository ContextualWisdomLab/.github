## 3. Ordered execution gates

1. **Prove the operational trust boundary.** Retain the existing credential-free
   prelease results. The operator reported two completed fresh boots, private
   endpoint timeouts, public DNS/HTTPS positives and cleanup with original VM
   and Docker PIDs preserved. These point probes explicitly do not establish
   kernel-enforced whole-network denial, complete per-job reset or runner
   registration. Independently bind the retained receipt before promotion.
2. **Settle one existing registration custodian.** Establish its actual
   management route and in-flight state. Admit only reviewed image/tool and
   clean-per-job lifecycle with minimum repository/workflow access. A
   `cwlab-ci-isolated` label alone is not isolation or capacity proof. Do not
   repurpose persistent privileged control, scanner or inference guests for
   arbitrary PR code.
3. **Integrate routing through ordinary gates.** Preserve trusted central-main
   workflow/group guards. Untrusted and non-main execution uses only the
   isolated pool, with no hosted fallback. Preserve OS/architecture/version
   matrices, action pins, check identities, permission boundaries and fork
   admission. Resolve stack prerequisites without importing unrelated work or
   treating branch integration as main shipment.
4. **Verify repository and service-managed consumers separately.** Repository
   CI/Fuzz/Scorecard YAML, reusable callers and CodeQL default setup are
   separate routing surfaces. A central workflow patch changes none of these
   by implication. Require actual runner identity, executed steps and terminal
   result on the intended event/head/source for each requested surface.
5. **Recover actual reviewers.** Keep source repairs, formal approval and
   runtime receipt distinct. Noema verdict publication, Strix source-grounded
   report and OpenCode substantive exact-head review must all be real. A
   successful skipped job, comment, transport preflight or synthetic status is
   not a qualifying review.
6. **Release only after current-head reconciliation.** Re-fetch exact head,
   base, review threads, required checks and effective rules before review,
   retry, push or merge. A push invalidates preceding review/check evidence.
   Keep product gaps and original commitments active until ordinary protected
   integration and relevant end-to-end execution are verified.

Independent source fixes and read-only reviews may proceed during external
admission waits. Do not turn one unresolved administrator dependency into an
organization-wide prohibition on useful work or invent a numeric agent cap.

## 5. Actions process efficiency without weaker governance

Keep mechanical automation distinct from independent judgment.

- Coalesce superseded PR work at workflow admission by workflow, repository and
  PR identity, with trigger-aware collision-safe fallback. Do not include head
  SHA in that cancellation key. Preserve existing non-supersession serialization
  where stopping a shared job would discard valid evidence.
- Cancel only positively identified superseded work for the same PR. Bind
  `pull_request_target` and `repository_dispatch` targets from their validated
  payload/run association, never the control-plane top-level `head_sha`.
- Keep cleanup repository-local and event-driven. Do not add an organization
  queue sweep, another polling timer or speculative rerun to compensate for an
  admission defect. Reconcile ambiguous dispatch effects before retrying.
- Separate metadata admission, sandbox coverage/build, model/scanner work and
  terminal publication. A singleton scanner runner should not be needlessly
  occupied by passive settlement polling when the existing continuation
  contract can preserve authoritative evidence.
- Do not infer model failure from elapsed time. Section 8 of
  [the standing directive](product-goal-directive.md) accepts more than two
  hours per model and prioritizes correctness. Improve admission/continuation
  and use explicit provider terminal signals instead.
- Consume an existing owner's named receipt before issuing another query or
  task. Report changed results and precise next gates, not repeated unchanged
  blocker messages. Track enqueue, read/acceptance, source publication,
  execution and protected integration separately.
