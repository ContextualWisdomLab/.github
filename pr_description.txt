💡 What:
`scripts/ci/redact_sensitive_log.py`에서 여러 정규표현식 패턴(PROVIDER_TOKEN_RES)을 `|` (alternation) 연산자를 사용하여 단일 모듈 레벨 컴파일 정규표현식으로 통합했습니다.

🎯 Why:
대용량 CI 로그의 문자열 처리 시 발생하는 심각한 O(N) 성능 오버헤드를 방지하기 위함입니다. 이전에는 `_redact_unstructured` 함수가 `PROVIDER_TOKEN_RES`의 각 패턴을 순차적으로 반복하며 전체 로그 페이로드에 대해 `.sub`를 호출했습니다. 이로 인해 대규모 텍스트 페이로드에 대해 중복된 전체 길이 반복이 발생했습니다. 이번 최적화를 통해 텍스트 페이로드에 대한 단일 `.sub` 패스로 로직을 단순화했습니다.

📊 Impact:
중복 스캔 패스를 단일 패스로 줄여, 대용량 로그에 대한 정규표현식 폴백(fallback) 마스킹 로직의 실행 시간을 약 70% 단축했습니다 (8.36초 -> 2.42초).

🔬 Measurement:
1. 로컬 환경에서 `benchmark_regex.py`를 작성하여 대용량 합성 로그 텍스트를 대상으로 전/후 성능을 측정했습니다.
2. `pytest tests/test_organization_commercial_readiness_token_redaction.py`를 실행하여 모든 테스트가 정상 통과함을 확인했습니다.
